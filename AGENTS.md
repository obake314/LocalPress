# figma-make-app

React + Vite + Tailwind CSS project running inside Figma Make.

## Development Server

A Vite development server is **already running** on `$PORT` (default 8443). You don't need to start it manually.

- Preview URL: The user can access the running app through the preview panel
- Hot reload: Changes to source files are reflected immediately

## Project Structure

This is the canonical project structure. Start with task-relevant files below. Only follow imports or inspect other files when required, when a documented path is missing, or when the repository contradicts this guide.

- `src/main.tsx` - React entrypoint; imports `src/index.css` and mounts `src/App.tsx` into the `#root` element
- `src/App.tsx` - Primary application component and the usual starting point for UI work
- `src/index.css` - Global CSS entrypoint. Imports Tailwind CSS v4 and the files in `src/styles/`
- `src/styles/fonts.css` - Google Fonts `@import` statements (must stay first in the cascade)
- `src/styles/theme.css` - Design tokens in the Tailwind v4 `@theme` block (colors, type scale, radii, container width)
- `src/styles/base.css` - Element-level defaults (box-sizing, html/body, headings, selection, scrollbar)
- `src/styles/utilities.css` - Project-specific `@utility` definitions (`eyebrow`, `hairline`)
- `index.html` - Vite HTML shell containing the `#root` element and loading `src/main.tsx`
- `package.json` - Project dependencies and the Vite build, development, preview, and formatting scripts
- `vite.config.ts` - Vite configuration with React, Tailwind CSS v4, and Figma Make plugins plus the `@` alias for `src`
- `src/data/content.ts` - The single content entry point every page imports. Serves microCMS data when pulled, otherwise the mock data
- `src/data/content.generated.ts` - Generated by `pnpm content:pull`. Do not edit by hand
- `src/data/mockData.ts` - Types and sample data used until microCMS content is pulled
- `scripts/pull-content.mjs` - Build-time fetch from microCMS
- `microcms/SETUP.md` - How the microCMS admin is wired up and which fields to create
- `collector/` - Verified list of the 33 Iwate municipality feed sources, plus one-off checking scripts
- `server/` - The collection service deployed to Render. Receives the microCMS webhook and writes to `feedItems`
- `render.yaml` - Render Blueprint for the collector service and the static site
- `.mise.toml` - Toolchain versions for Node.js and pnpm

## Dependencies

- Runtime: React 19 and React DOM 19
- Styling: Tailwind CSS v4 with the `@tailwindcss/vite` plugin
- Build tooling: Vite 8, TypeScript 5.7, and `@vitejs/plugin-react`
- Formatting: oxfmt

## Styling

This project uses **Tailwind CSS v4** through the `@tailwindcss/vite` plugin configured in `vite.config.ts`. `src/index.css` imports Tailwind with `@import 'tailwindcss';` and then the split files under `src/styles/`. This scaffold does not need a Tailwind config file or PostCSS config.

Use Tailwind utility classes directly in JSX. Put new colors, font sizes and other design tokens in `src/styles/theme.css`, element defaults in `src/styles/base.css`, and custom utilities in `src/styles/utilities.css`. Do not hardcode arbitrary values such as `bg-[#1f6b4b]` in components — add a token and reference it (`bg-primary`). Corners are square throughout: the `--radius-*` tokens are all `0`, so avoid `rounded-*` classes.

`src/main.tsx` imports `src/index.css`, so global font wiring belongs in `src/styles/fonts.css`. Keep CSS `@import` statements first in the file, then add any `@font-face` rules there; the font-family defaults live in `src/styles/theme.css`.

## Content

There is no in-app admin screen. Editing happens in the microCMS dashboard, and content is pulled at build time by `pnpm content:pull`, which rewrites `src/data/content.generated.ts`. Pages must import from `src/data/content.ts`, never from `mockData.ts` directly.

The API key lives only in `.env` (gitignored) and is read by the pull script. Never fetch microCMS from the browser: this is a serverless SPA, so the key would ship in the bundle, and the free plan stops the API at 20GB/month with only one key available. See `microcms/SETUP.md`.

## Code quality

- Use double quotes for strings containing apostrophes (`"We're here to help"`), or escape them in single-quoted strings. An unescaped apostrophe in a single-quoted string breaks the build.
- Ensure JSX tags are closed and braces are balanced.
- Export components as default exports.
