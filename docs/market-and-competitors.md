# 自治体市場と競合

事業の前提になる数字と、同じ領域にいるサービスの整理。
出典は Labid Journal の記事群と、そこから辿れる一次資料。読んだのは 2026-08-22。

---

## 市場の規模

| 年度 | 自治体向けソリューション市場 | 前年比 |
|---|---|---|
| 2022年度 | 約 7,595億1,000万円 | +4.4% |
| 2023年度（予測） | 7,733億7,000万円 | +1.8% |

出典: 矢野経済研究所

参考として、**1,741市区町村の基幹系システム等の運用経費**は平成29年度当初予算で
**合計 4,786億円**（総務省）。

## 成長と減少の要因

**2025年度までの押し上げ要因は「自治体DX」**、特に基幹系（住民情報系）システムの
標準化。従来は自治体ごとに個別のデータベース・サーバーを構築し、仕様が共通化されて
いなかった。新型コロナ対応でこの個別最適が国との連携を妨げたことが表面化し、
政府は2025年度末を目標に標準化を決定した。

**2026年度以降は微減の見込み。** 標準化が完了すると、既存ベンダーが受けていた
保守・運用の発注が無くなるため。ただし減少幅は小さいと見られている。

**中長期では社会課題解決に向けて伸びる**という見立て。政府の
「デジタル田園都市国家構想」（2021年〜、総合戦略は2023年改訂・2027年目標）が
官民連携を後押しし、自治体から民間への投資は増えると考えられている。

構想が掲げる課題は3点。

- 人口減少・少子高齢化（出生率 1.45〔2015〕→ 1.33〔2020〕）
- 過疎化・東京圏への一極集中（東京圏転入超過 80,441人〔2021〕）
- 地域産業の空洞化（都道府県別労働生産性格差 最大1.5倍〔2018〕）

> **LocalPress にとって**
> 事業計画の裏付けに使える数字。特に「自治体ごとに仕様も公開方法もばらばら」
> という構造は、情報収集の難しさの原因そのものであり、
> それを解消することがサービスの価値になる。

## 自治体の予算サイクル

自治体営業のタイミングを決める。民間と同じ感覚で動くと外す。

| 時期 | 何が起きるか | 事業者側 |
|---|---|---|
| 4月〜6月 | 職員の情報収集期。4月〜5月上旬は人事異動と引継ぎで多忙 | 5月中旬以降が接触しやすい。関係構築 |
| **7月〜9月** | 各部で次年度事業を計画。予算要求の骨格が決まる | **提案・見積の黄金期。ここで採用されれば入札で優位** |
| 9月〜10月 | 首長から財政運営方針（予算編成方針）が発表される | 重点投資分野が分かる。各自治体のHPで公表される |
| 10月 | 各部から財政課へ予算要求 | 提案内容や見積が正式な要求に反映される |
| 11月〜12月 | 財政部の査定・審査・内示 | — |
| 1月 | 首長の査定・審査・内示 | — |
| 2月〜3月 | 議会審議・可決 | 議会対応で接触困難 |

### 予算の種類

| 種類 | 内容 |
|---|---|
| 当初予算（本予算） | 年度開始前に成立する年間予算。**最も重要** |
| 補正予算 | 調製後の事由で追加・変更が必要になったときに組む。国の補助金決定、災害対応、新政策など |
| 暫定予算 | 年間予算が年度開始前に成立しない場合の、つなぎの予算 |
| 骨格予算 | 首長・議員選挙があるため政策的経費を避け、人件費など最小限を計上した予算 |
| 肉付予算 | 骨格予算の後に政策的経費・新規事業を追加する補正予算 |

> **LocalPress にとって**
> **予算編成方針は各自治体のHPで公表される。** 重点投資分野が書かれており、
> 事業者にとって価値が高い。入札公告より前の段階の情報で、
> 現状の収集対象に入っていない。分野として立てる価値がある。
> 「9月〜10月に各自治体の予算編成方針を集めて出す」は、
> 入札情報の後追いではない独自の切り口になりうる。

## 競合: Labid（ラビッド）

| | |
|---|---|
| 運営 | Nehan株式会社 |
| URL | https://labid.jp/ |
| 位置づけ | 公共営業のための AI ワークフロー。「知るところから勝つところまで、ひとつのプラットフォームで」 |

### 機能

- 全国の**入札情報と落札情報**を収集
- 新着案件を**毎日メールや Slack で通知**
- **AI が仕様書を要約**
- 事業内容に合致した案件を**AI がレコメンド**（表記揺れに対応すると主張）
- 案件管理

### 規模

サイトマップ（`https://labid.jp/sitemaps/sitemap.xml`、8分割）に
**`/projects/` が 320,923 件**登録されている。1案件1ページで公開しており、
検索流入を取りにいく構成。

対して LocalPress の現在の掲載は約 900 件（岩手・宮城・新潟）。**桁が3つ違う。**

### コンテンツ戦略

記事・お役立ち資料・導入事例・ポッドキャスト・セミナーを揃えている。
記事本文はサーバー側で描画され、検索エンジンから読める。
一方で**記事一覧とカテゴリページはクライアント側描画で中身が空**という作りで、
一覧からの回遊より検索流入を重視していると読める。

### サイトの作り（技術面のメモ）

- CloudFront で UA によるアクセス制限。ブラウザ以外の User-Agent は 403 になる
- `robots.txt` は `Allow: /` のみで、クロール自体は許可している
- サイトマップに載っているのは `/projects/` だけで、記事は入っていない

### 差別化の観点

Labid は**事業者向けの営業支援ツール**として作られている。
LocalPress は事業計画上、**自治体情報のプラットフォーム**であり、
入札はその一分野という位置づけ。イベント・補助金・生活情報を含む点、
自治体別・地域別の導線を持つ点が構造的に違う。

Labid 自身が「自治体案件に特化したサービス」を有料サービス比較表の一類型として
挙げており（地域別・業種別・発注部局別の検索、プロポーザル情報の充実）、
**地域特化は成立する型として認識されている。**

> **LocalPress にとって**
> 網羅件数で正面から competing するのは現実的でない。
> **地域を軸にした導線と、入札以外の自治体情報を併せ持つこと**が差になる。
> ただし収集の網羅性は最低限の信頼要件なので、
> 対象地域の中では取りこぼさない状態を作る必要がある。
