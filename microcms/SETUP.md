# microCMS で管理画面を用意する

LocalPress は管理画面を自前で持たず、**microCMS の管理画面をそのまま運用画面として使う**構成にしています。
編集は microCMS 上で行い、サイト側はビルド時に取り込みます。

```
microCMS の管理画面（編集・入稿）
        │  Content API (GET)
        ▼
pnpm content:pull        ← ローカル／CI でのみ実行。APIキーはここだけ
        │
        ▼
src/data/content.generated.ts   ← 静的なTSとして固まる
        │
        ▼
src/data/content.ts → 各ページ
```

## なぜブラウザから直接叩かないのか

このアプリはサーバーを持たない SPA です。ブラウザから microCMS を呼ぶと、
API キーが配信される JS に埋め込まれ、誰でも読み取れる状態になります。
Hobby（無料）プランは **データ転送 20GB/月で、超過すると API が停止** し、
**API キーは1本しか発行できない**ため、キーが漏れると第三者に停止させられます。

そのため取得はビルド時に一度だけ行い、結果を静的ファイルに固めています。
編集内容をサイトに反映するには `pnpm content:pull` を実行してから再ビルドします。

## 手順

### 1. サービスを作る

[microCMS](https://microcms.io/) でアカウントを作り、サービスを1つ作成します。
管理画面の URL `https://XXXX.microcms.io` の `XXXX` がサービスIDです。

### 2. API を2つ作る

いずれも **リスト形式** で作成します。無料プランは API を5個まで作れるので枠内に収まります。

#### API 1：自治体（エンドポイント `municipalities`）

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `code` | 団体コード | テキストフィールド | ✓ | 全国地方公共団体コードの5桁。`3201` のように先頭の0を落として入れても、取り込み時に `03201` へ補正します |
| `name` | 自治体名 | テキストフィールド | ✓ | 例 `盛岡市` |
| `prefecture` | 都道府県 | テキストフィールド | | 未入力なら `岩手県` |
| `population` | 人口 | 数字 | | |
| `area` | 面積(km²) | 数字 | | |
| `website` | 公式サイト | テキストフィールド | | `https://` から |
| `summary` | 紹介文 | テキストエリア | | 未作成でも動きます（自治体ページの説明文が出なくなるだけ） |

#### API 2：掲載情報（エンドポイント `articles`）

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `title` | タイトル | テキストフィールド | ✓ | |
| `cityCode` | 自治体コード | テキストフィールド | ✓ | `municipalities` の `code` と一致させる |
| `cityName` | 自治体名 | テキストフィールド | ✓ | |
| `prefecture` | 都道府県 | テキストフィールド | | 未入力なら `岩手県` |
| `category` | 分野 | セレクトフィールド（単一選択） | ✓ | 下記の7値 |
| `status` | 状態 | セレクトフィールド（単一選択） | ✓ | 下記の4値 |
| `targets` | 対象者 | セレクトフィールド（複数選択） | | 下記の6値 |
| `deadline` | 締切日 | 日時 | | |
| `summary` | 概要 | テキストエリア | ✓ | 一覧カードに出る |
| `body` | 本文 | テキストエリア | | 改行はそのまま表示される |
| `sourceUrl` | 元ページURL | テキストフィールド | ✓ | 自治体の公開ページ |
| `amount` | 金額・規模 | テキストフィールド | | 例 `上限100万円` |
| `tags` | タグ | テキストフィールド | | カンマ区切り。例 `補助金, DX, 中小企業` |

公開日は microCMS が自動で持つ `publishedAt` を使うので、フィールドを作る必要はありません。

**セレクトの選択肢（表記をそのまま登録してください）**

- `category`：`イベント` / `補助金` / `入札・公募` / `募集` / `文化` / `子育て` / `政策`
- `status`：`募集中` / `締切間近` / `終了` / `準備中`
- `targets`：`個人` / `企業` / `団体` / `子育て世帯` / `高齢者` / `農業者`

想定外の値が入っていた場合、取り込み時に既定値へ寄せます（`category` は `政策`、`status` は `募集中`）。

### 3. API キーを発行して .env に書く

「サービス設定 > APIキー」で GET 権限のあるキーを用意し、リポジトリ直下に `.env` を作ります。

```bash
cp .env.example .env
```

```
MICROCMS_SERVICE_DOMAIN=あなたのサービスID
MICROCMS_API_KEY=発行したキー
```

`.env` は `.gitignore` 済みです。コミットしないでください。

### 4. 取り込む

```bash
pnpm content:pull
```

`src/data/content.generated.ts` が書き換わり、開発サーバーなら即座に画面へ反映されます。
**取り込む前は `src/data/mockData.ts` のサンプルデータが表示されます**（現在の状態）。
今どちらを表示しているかは `contentSource`（`"microCMS"` / `"mock"`）で判別できます。

## うまくいかないとき

**`fetch failed` と出る**
`MICROCMS_SERVICE_DOMAIN` にサービスIDだけが入っているか確認してください。
`https://` や `.microcms.io` が付いていても取り除くようにしてありますが、
IDそのものが違うと名前解決に失敗します。

**HTTP 401 / 403**
APIキーが違うか、GET 権限が付いていません。「サービス設定 > APIキー」を確認してください。

**HTTP 404**
エンドポイント名が違います。microCMS 側の API のエンドポイントが
`municipalities` / `articles` になっているか確認してください。

**自治体名は出るのに人口・面積が 0 になる**
`population` / `area` が未入力です。値が入っていないフィールドは画面に出さないので、
0 と表示されることはありませんが、入力すれば自治体ページに並びます。

**記事の自治体リンクが切れる**
記事の `cityCode` が `municipalities` の `code` と一致していない可能性があります。
両方とも5桁（例 `03205` 花巻市）でそろえてください。岩手県の市部は
盛岡 03201 / 宮古 03202 / 大船渡 03203 / 花巻 03205 / 北上 03206 / 久慈 03207 /
遠野 03208 / 一関 03209 / 陸前高田 03210 / 釜石 03211 / 二戸 03213 /
八幡平 03214 / 奥州 03215 / 滝沢 03216 です（03204 は欠番）。

## 運用上の注意

- **反映にはビルドが要ります。** microCMS で編集しただけではサイトは変わりません。
  自動化するなら microCMS の Webhook でデプロイを叩く構成にします。
- **1回の取り込みでのAPI呼び出しは、100件ごとに1リクエスト**です（`limit` の上限が100のため分割）。
  10,000件でも100リクエスト程度で、無料枠の転送量には十分収まります。
- 無料プランの上限：メンバー3名 / API 5個 / コンテンツ 10,000件 / 転送量 20GB月 / APIキー1本。
- 下書き・プレビュー機能を使う場合は `draftKey` の受け渡しが要るため、この静的取り込み構成とは別に検討が必要です。
